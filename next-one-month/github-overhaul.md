For a senior data engineer with 9 years of experience—especially one with a track record of slashing costs by 80% at companies like Walmart—your open-source contributions should scream "Architectural Depth" and "Platform Maturity." Contributing to a major project's core is high-signal, but for the $60\text{L}+$ remote market, contributing to the connectors and interoperability layers between these tools and GCP is often more valuable. It proves you can solve the "last-mile" engineering problems that block billion-dollar enterprises.Here are 5 open-source projects perfectly aligned with your Scala/Python/Spark stack and GCP focus:

1. Apache Beam (Python SDK & GCP IO)Beam is the backbone of Google Cloud Dataflow. Since you are comfortable with Python and Spark, this is your highest-impact option.Why it stands out: It proves you understand unified batch and streaming models, a requirement for senior remote roles.GCP Fit: Focus on the apache-beam[gcp] library.Where to contribute: Look for issues in the BigQuery IO or Pub/Sub Lite connectors. Specifically, implementing "Managed Iceberg" writes from Beam to BigQuery is a massive 2026 trend.Action: Search GitHub for labels: component: io-python-gcp or good-first-issue.

2. dbt-bigquery (The BigQuery Adapter for dbt)As companies move away from custom ETL toward ELT, dbt-bigquery has become the standard for SQL-based transformations.Why it stands out: It shows you can manage complex dependencies and data modeling at scale.GCP Fit: This is a pure GCP-native repository.Where to contribute: Look into implementing or refining Incremental Materializations or improving how dbt handles BigQuery Search Indexes. These are advanced features that save companies significant money on query costs.Action: Visit the dbt-labs/dbt-bigquery repo and check the "Discussions" for upcoming feature requests.

3. Apache Iceberg (Spark-Scala Runtime)Iceberg is the leading open-source table format for "Data Lakehouses." It is now natively supported by BigQuery (via BigLake) and Dataproc.Why it stands out: This is the most "Senior" tech on the list. It proves you understand storage optimization, file compaction, and ACID transactions in distributed systems.Stack Fit: Uses Scala for its core Spark connectors.Where to contribute: Contribute to the spark-runtime module. Focus on Metadata Cleanup or Compaction Strategies—which directly correlates to the "cost-saving" narrative in your resume.Action: Look for issues tagged spark or python (for PyIceberg) in the Apache Iceberg repo.

DataHub (GCP Ingestion Source)DataHub (created by LinkedIn) is the leading data catalog for observability.Why it stands out: At your seniority, companies pay for Governance as much as for Pipelines. 5. Spark-on-k8s-operator (GCP/GKE focus)As you move your local projects to GitHub and K8s, this project is the industry standard for running Spark on Kubernetes.Why it stands out: It bridges the gap between Data Engineering and DevOps, a "Force Multiplier" skill that justifies a $60\text{L}+$ salary.GCP Fit: Originally developed by Google; it is the default way to run Spark on GKE.Where to contribute: Help with GCP Workload Identity integration or improving the Dynamic Resource Allocation logic on GKE.Action: Check the GoogleCloudPlatform/spark-on-k8s-operator issues.
